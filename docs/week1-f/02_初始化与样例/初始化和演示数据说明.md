# 初始化与演示数据

## 从空库开始

本目录的 `schema.sql` 和 `data.sql` 是上游指定提交的逐字节副本。第一个文件建表和约束，第二个文件写入课程与选课记录。测试账号由应用启动时加载。脚本预期数据如下。

| 登录名 | 角色 | 默认可见课程 | 第一周验收用途 |
|---|---|---|---|
| admin | 系统管理员 | CS101、SE101 | 检查身份、管理菜单和课程范围 |
| teacher | 教师 | CS101、SE101 | 向本人任教的课程上传、发布和下架样例 |
| student | 学生 | CS101《计算机导论》，课程 ID 1 | 查看 CS101 已发布资料，打开引用，下载同一份原文件 |
| student2 | 学生 | SE101《软件工程》，课程 ID 2 | 查看 SE101；访问 CS101 的讲义和原文引用应被拒绝 |

在 Windows 上用独立测试库复测，直接按[测试复现说明](../03_验收与证据/复现说明.md)运行。随包验证程序新建一次性数据库服务、设置随机凭据并在退出时关闭服务。它会核对空库建表、重复初始化、选课唯一性、外键和级联关系。

如组员已有**专用空库**，可在此目录启动 MySQL 命令行，登录该空库后依次执行以下 SQL。数据库名及账号由小组自己的测试环境提供。初始化 SQL 使用固定 ID；对已有业务数据的库，需要先核对 ID 和课程编码。

```sql
SOURCE schema.sql
SOURCE data.sql
SELECT c.course_code, c.name, e.student_username
FROM campus_course c JOIN campus_course_enrollment e ON e.course_id=c.id
ORDER BY c.id, e.student_username;
```

结果应为 `CS101 / 计算机导论 / student` 和 `SE101 / 软件工程 / student2`。新库应有 4 张业务表，资料和片段行数均为 0。重复执行两份脚本后，在此基线下行数保持相同。日常调试的默认 H2 内存库会随进程结束丢失数据；重启复验请使用文件 H2 或独立 MySQL。

## 样例资料与预期证据

五份文件随包保存在[样例资料](样例资料/)目录。上游将其标为项目开发者自编的开发材料；来源和用途见[原作者说明](样例资料/README.md)及[固定检索样例说明](https://github.com/sjyEva/CampusAI/tree/02574248ab37e38eeacaf15bf81a8990fed9d8fa/docs/rag/evaluation)。来源文件、SQL 和校验值见本目录的 `来源与SHA256.md`。

| 文件 | 建议测试课程 | 可提出的问题／搜索词 | 应核对的原文位置 |
|---|---|---|---|
| parsing-demo.pdf | CS101 格式验收 | How does BM25 rank text? | 第 1 页出现“BM25 ranks text chunks”；返回真实 PDF 页码。 |
| parsing-demo.docx | CS101 格式验收 | 资料状态 | 第 8 段表格包含“解析成功且已发布”；返回段落范围。 |
| parsing-demo.txt | CS101 格式验收 | 物理行编号 | 第 5 行说明 TXT 按原始物理行编号，空行占号；返回范围应覆盖第 5 行。 |
| course-1-evaluation.txt | CS101 固定评估 | 一个字节通常包含多少比特？ | 第 3 行说明一个字节通常由八个比特组成。 |
| course-2-evaluation.txt | SE101 固定评估 | 软件需求的验收标准应该怎样表达？ | 第 1 行说明验收标准应写成可以观察和核对的条件。 |

格式验证可按 PDF、DOCX、TXT 依次上传并核对。固定检索评估另用两门课程的指定语料，避免混入额外讲义改变排名。真实教师课件如用于演示，由组员记录提供者、允许用途及取得日期。
