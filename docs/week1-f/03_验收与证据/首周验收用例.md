# 首周验收用例与后续交接

适用范围为给定主分支、全新测试库及随包自编资料。除说明外，每个 HTTP 用例使用真实本机后端。下表定义预期结果；执行结论与日志索引见本目录的《首周实测报告》。

| 编号 | 操作与输入 | 预期结果 | 执行入口 |
|---|---|---|---|
| DB01 | 空库执行建表、种子 SQL | 4 张表；课程、选课、资料、片段分别为 2、2、0、0 行 | VerifyH2 / verify_mysql |
| DB02 | 在同一库再执行两份 SQL | 同样的 4 张表与行数，种子关系保持一致 | 同上 |
| DB03 | 连接课程与选课表，按课程查询 | CS101 对应 student，SE101 对应 student2 | 同上 |
| DB04–06 | 重复选课；插入无对应课程的选课；删除仍有选课的课程 | 三次独立操作均被预期约束拒绝 | 同上 |
| DB07 | 写入临时资料及片段，删除资料，在事务中查询片段 | 子片段计数 0；随后回滚 | 同上 |
| API01 | 匿名获取课程；错误密码登录；正常登录后退出再读取身份 | 无课程数据或有效令牌；退出的令牌失效 | 上游 verify-api |
| API02 | 四个账号依次获取身份、菜单、课程列表和详情 | 学生各见一门；教师与管理员见两门；学生不能看管理菜单或未选课程详情 | 上游 verify-api |
| RAG01 | 教师上传带唯一词的 TXT，分别在发布前后搜索 | 草稿无命中；发布后命中该资料且有原文位置 | 上游 verify-rag |
| RAG02 | 未选课学生搜索、下载；学生执行资料删除 | 前两项业务码 404，删除业务码 403 | 上游 verify-rag |
| RAG03 | 重处理、下架、替换资料，尝试使用旧版本标记或旧引用 | 重处理保持版本；下架使引用失效；替换产生未发布的新版本，旧版本操作被拒绝 | 上游 verify-rag |
| SRC01–03 | 三种样例逐个上传、发布、搜索、打开引用并下载原件 | PDF 第 1 页；DOCX 范围含第 8 段；TXT 范围含第 5 行；原文匹配、下载字节一致 | verify_http |
| SCOPE01 | student2 使用 CS101 的引用 ID，分别走 CS101 路径和本人的 SE101 路径 | 两条路径均返回业务码 404，响应没有来源数据 | verify_http |
| AI01–02 | 无模型配置下问资料内问题，再问一个不存在的唯一词 | 有依据时返回检索回退和正确原文；无依据时返回 no_evidence，证据与引文列表为空 | verify_http |
| PERSIST01 | 保留已发布的 TXT，重启应用；先用旧令牌，再重新登录 | 旧令牌失效；新会话仍能打开同一引用并下载相同字节 | verify_http |
| WEB01 | 管理端安装锁定依赖、运行模块回归和生产构建 | 测试无失败；生成可部署静态资源 | npm ci / test / run build |
| MINI01 | 干净副本标准安装，随后在候选副本锁定安装并分别构建 | 标准安装应完成；候选副本应生成 H5 入口与微信 app.json | npm 安装与构建日志 |

## 小组环境验收

| 待办 | 实施条件 | 保留的证据 |
|---|---|---|
| 六名成员复用同一套数据 | 各成员检出同一提交；按准备说明初始化自己的测试环境，或连接团队统一测试环境 | 成员、提交号、数据库版本、两行选课输出、遇到的问题 |
| 微信登录及两端界面 | C 提供团队 AppID 和设备，D 提供管理端；先确认真实接口已接通的范围 | 学生切换后的课程列表、教师入口、设备和后端版本；由实际操作者截图 |
| 讲义授权及真实提问 | 教师提供允许演示的资料，预先记录允许用途；另行固定人工标注的问题和支持段落 | 授权来源、题集版本、人工标注者、逐题命中与误召回 |
| 历史、反馈、练习、统计 | 对应真实接口交付，B、D、F 约定统计口径 | 已知输入记录、手算期望值、接口返回值和差异 |
| 真实模型生成与外部部署 | 由部署负责人提供授权环境与模型额度 | 请求时间、返回状态、核对过的引文与独立复核人 |

缺陷记录格式：编号、版本、环境、输入与步骤、预期结果、实际结果、影响、负责人、修复版本、复测结果。组内验收签字与日期由实际参与者填写。
