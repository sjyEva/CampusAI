# 固定检索样例与首轮结果

本目录的 40 个问题和两份课程文字由开发者为功能验证自编，不是教师课件或真实学生调查。题目按开发集和验收样例各 20 题固定，每组包含 15 个有依据问题和 5 个无依据问题。两份语料分别对应种子课程 1「计算机导论」与课程 2「软件工程」，各含 15 个知识主题。

全部题目、原文和标注在第一次运行前固定。验收样例没有由 F 独立标注和保管，因此本文中的 acceptance 只表示预先固定的一组开发者验收样例，不能称为独立盲测。首次结果已经保存在 `baseline-results.json` 和 `baseline-results.md`，后续测试只覆盖 `backend/target/` 中的输出，不自动覆盖这些首轮记录。

## 复现

在仓库根目录执行：

```powershell
.\backend\mvnw.cmd -f backend/pom.xml "-Dtest=RagEvaluationTest,Bm25EngineTest" test
```

测试使用项目实际的 `DocumentParser` 和 `Bm25Engine`，不使用预设检索结果或模型生成结果。运行后查看：

- `backend/target/rag-evaluation-results.json`：逐题问题、来源标注、Top 3 片段、BM25 得分、检索词覆盖率和耗时。
- `backend/target/rag-evaluation-results.md`：集合统计与逐题通过情况。

每题的 gold 是原文中的精确引文与段落位置；TXT 段落编号采用 1 起始物理行号，空行也计入编号。测试先用真实解析结果核对引文和位置确实存在，再检查前三个检索结果是否包含这些来源片段。源文件哈希写入 `questions.json`，题集自身 SHA-256 固定在测试内，避免无意中更改验收数据。

固定 v1 题集 SHA-256：`db2a6a4c442d2098683d68290e97483720d581ac361c2aabe04665ee5863e616`。Git 属性对参与哈希的三个文本文件关闭自动换行转换，保留首次评估时的原始 CRLF 字节，确保跨平台检出时校验一致；并非禁止文本差异审查。以后如需变更语料或题目，应发布新数据版本，并保留本版首次结果。

## 指标与首轮观察

Hit@3 的分母仅为有依据问题数：前三个结果包含标注支持片段的问题数 / 有依据问题数。无依据问题单独检查是否返回空结果，不混入 Hit@3，也不把未达到预期的题目删除。

2026-11-23 首轮运行使用 Java 17、SmartChineseAnalyzer 9.12.3、BM25 k1=1.2、b=0.75、最低检索词覆盖率 0.5、片段上限 700 字符、TopK=3。

| 集合 | 有依据问题 Hit@3 | 无依据问题正确空结果 | 无依据问题误召回 |
|---|---|---|---|
| development | 15/15 | 2/5 | 3/5 |
| acceptance | 15/15 | 4/5 | 1/5 |

首轮有依据样例达到计划的 12/15 目标，但两门课程均只有 5 个解析片段，题目由开发者根据这些短资料撰写。这是一个小规模、可复现的功能检查，不能据此声称真实课程检索准确率为 100%。后续需要加入获授权的真实课程资料、更多干扰片段和由其他成员独立提出的问题，再重新评估。

四个无依据误召回分别是 U02（最优页面置换）、U03（MC/DC）、U05（两阶段提交）和 U07（DNSSEC 密钥轮换）。资料中包含分页、覆盖率、事务或域名相关词语，有的段落还明确说明不介绍所问细节。词面匹配因此能找到相关段落，却不能证明这些段落回答了问题。该结果保留了 BM25 的实际局限，没有依据验收结果修改排序参数或题目。

检索词覆盖率是命中不同查询词的比例，不是答案置信度。BM25 得分也不是概率，不能跨不同问题直接比较。实际问答必须继续区分「候选原文」与「已生成回答」；引用编号有效和支持引文确实存在，仍不等于模型结论获得语义支持。

该评估不衡量生成答案正确率、真实模型供应商可用性、吞吐量或端到端延迟。JSON 中的耗时来自一次本地测试，包含分词和临时索引构建，受 JVM 预热影响，仅便于检查运行情况。权限、版本更新、下架与模型故障由相应的集成及模型适配测试验证。
