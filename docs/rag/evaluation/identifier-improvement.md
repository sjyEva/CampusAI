# 显式技术标识符检索改进

本轮保持 BM25 参数、中文分词、查询词去重和 0.5 词项覆盖门槛不变，增加一个候选资格判断：问题明确点名的技术标识符必须出现在候选片段原文中。它针对的是分词后标识符被拆开、普通相关词覆盖了问题的情况，不是语义推理或答案支持判定。

例如提问 `MC/DC 测试覆盖` 时，仅包含“测试、覆盖率”的段落不能因此进入结果；包含完整 `MC/DC` 的段落才继续参与排序。`C++` 与 `C`、`C#` 区分，`BM25` 不因 `BM250` 出现而满足条件。匹配经过 NFKC 和大小写归一，保留技术标点。带空格和紧邻写法的版本名（如 `Java 21` 与 `Java21`）可核对为同一版本，但不会把 Java 17 当作 Java 21。

识别范围：

- 字母数字混合标识，例如 BM25、Java17。
- 含 `/`、`.`、`_`、`-`、`+`、`#` 的完整标识，例如 MC/DC、Node.js、SHA-256、C++。
- 全大写标识（含 C 等单字母名称）、含内部大小写变化的标识（如 PostgreSQL），以及中英混合问题中明确出现的非问句英语词；排除常见冠词、介词、问句词及章节/页码等位置用语。
- `BM25-based` 仍明确提到 BM25，因此候选原文中的连字符复合词允许其中的完整分量满足标识要求。查询完整的 `SHA-256` 仍需匹配完整标识。

普通英文问句继续使用词干匹配，例如 `testing` 可检索到 `Tests`；整句全大写、含至少三个英语词的输入不再仅凭大小写把每个词判成缩写（数字及技术标点规则仍有效）。普通中文问题不会额外要求整句精确匹配。该规则没有根据固定题目的编号、正确答案或特定中文失败短语做例外。

## 回归与评估约定

新增 `RetrievalRegressionTest` 的独立对照用例覆盖协议缩写、大小写与全角字母、符号语言名、版本、普通英文词干、普通中文问句、连字符分量及已知局限。原有 40 题及其语料、哈希、首次 `baseline-results.*` 不变。复测使用的仍是已经看过结果的样例，因此只能称为已知回归比较，不能重新包装成独立验收或未见测试。

当前代码定向复测共 18 项通过（BM25 8 项、新回归 9 项、固定评估 1 项）。实际逐题输出另存为 [improvement-results.json](improvement-results.json) 和 [improvement-results.md](improvement-results.md)，首次 baseline 继续保留。30 道有依据题仍全部命中前三；10 道无依据题正确空结果从 6 道增加到 7 道，U02、U03、U05 仍误召回。无依据题单独统计，不并入 Hit@3 分母，不隐藏剩余失败。

## 精度与召回的边界

这是有意保守的词面约束：资料若只写“超文本传输协议”而没有 `HTTP`，显式询问 HTTP 时可能漏召回。当前没有自动扩展中英文别名，也不把普通英文单词都当作必须精确匹配的标识。后续引入别名表前需要课程资料审核及单独的回归集。

片段出现标识仍不代表能回答问题：例如“本资料不介绍 TLS 1.3 握手细节”会通过标识检查。中文“最优页面置换”“两阶段提交”等概念缺失也不一定被此规则识别。模型引用校验和人工核对仍是必要步骤，不能把标识命中或词项覆盖率显示为答案置信度。
